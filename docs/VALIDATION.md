# 실행 검증 · 2026-10-18

현재 인스턴스에서 개발·빌드·가상 관람 기능을 검증했습니다. **실사급 서울 복원, 실제 사진과의 정합, 물리 GPU의 1080p·60fps 달성 판정은 미완료입니다.**

## 실행 환경과 결과

- Debian 13, AMD EPYC 가상 CPU 5개, 메모리 약 33GiB. `/dev/dri` 물리 GPU 없음.
- Node.js 24.19.0, npm 11.9.0, Chromium 154.0.8037.57.
- 실제 그래픽 경로: SwiftShader 소프트웨어 어댑터의 WebGL2. 소프트웨어 WebGPU 시험에서 장치 오류가 발생해, 앱은 소프트웨어 어댑터를 감지하면 WebGL2를 사용합니다. 물리 GPU의 WebGPU 경로는 미검증입니다.

## 측정값의 해석

통합 검증의 뷰포트는 1280×800, 낮은 화질의 내부 캔버스는 896×560입니다. 검사 중 기록한 애니메이션 콜백 간격은 중앙값 약 550ms, 95백분위 약 1533ms였습니다. 스크린샷·프리셋 변경·여러 탭 부하를 포함한 소프트웨어 렌더링 진단값이며, 실제 GPU 벤치마크가 아닙니다. 60fps를 달성했다고 주장하지 않습니다.

배포용 빌드는 별도의 1440×900 브라우저에서 균형·높은 화질로 검사했습니다. 마지막 높은 화질 프레임은 90 draw calls, 약 87.8만 삼각형을 기록했습니다. 반사와 그림자 등의 추가 패스를 포함하는 Three.js 프레임 통계입니다. 이 짧은 실행은 60프레임 표본에 도달하지 않아 프레임 시간 필드는 0(아직 집계되지 않음)이며 0ms 성능을 뜻하지 않습니다.

통합 보고서의 초기 `drawCalls`는 누적 `render.calls`를 잘못 읽은 값이었습니다. 원본을 보존하고 정리된 보고서에는 `renderCallsTotal`로 이름을 바로잡았습니다. 앱은 현재 프레임의 `render.drawCalls`를 읽도록 수정했고 배포 실행에서 검증했습니다.

## 재사용 환경 설정

`install_script`, `start_skill`을 설정 초안에 저장했습니다. 지리 검증 요청을 위해 `api.openstreetmap.org`, `en.wikipedia.org`를 사용자 지정 허용 도메인에 추가했고 기존 패키지 관리자 프리셋은 유지했습니다. 추가 시크릿은 필요하지 않습니다.

저장은 확인됐지만 현재 인스턴스의 네트워크 정책 적용이나 환경 게시를 뜻하지 않습니다. 재사용하려면 환경 설정에서 초안을 검토·저장한 뒤 게시해야 합니다. 게시·새 작업 복원은 별도로 검증해야 합니다.

사진측량·정밀 GIS 자산과 실제 사진을 확보한 뒤 [지리 검증 목록](GEOGRAPHY.md)에 따라 시점·지형·스케일을 교정하고, 실제 GPU에서 렌더링 예산을 측정하는 작업이 남아 있습니다.
